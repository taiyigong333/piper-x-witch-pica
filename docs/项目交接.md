> 本文是项目维护入口。每次修改采集流程、配置格式、输出目录或验证方式后，应同步更新本文。

## 1. 当前状态

- 项目：Piper-X、Pika Sense、RealSense 多模态数据采集系统。
- 当前分支：`Reverse-recording`。
- 主要入口：`src/taiyi_piper_x_collect/cli.py`。
- `session.reverse_recording_enabled` 默认 `true`，控制正向采集后是否继续反向采集。
- 双向采集入口：`teleop-session --reverse-recording`。
- 当前工作区存在未提交修改；提交前必须重新运行测试并检查 `git diff`。
- Git 分支名不能包含空格，因此用户要求的 “Reverse recording” 实际使用合法名称 `Reverse-recording`。

## 3. 双向采集约定

任务配置：`configs/tasks/grab_rotating_red_square_into_blue_plate.yaml`。

```yaml
session:
  batch_tag: 1
```

`batch_tag` 是人工维护的正整数。不同 tag 写入不同批次目录；同一个 tag 下的每次完整采集使用精确到微秒的采集时间目录。

一次完整采集固定包含两段：

1. `normal_trajectory.hdf5`：夹取旋转平台上的红色方块并放入蓝色盘子。
2. `reverse_trajectory.hdf5`：从蓝色盘子取出红色方块并放回旋转平台。

第二段采集时保持正常时间顺序，采集结束后才允许离线倒放；原始第二段数据必须保留，倒放结果应写入新的目录。

## 4. 输出目录

```text
<output_root>/batch_<batch_tag>/<采集时间>/
├── forward/normal_trajectory.hdf5
├── reverse/reverse_trajectory.hdf5
└── （批次根目录的 camera_parameters.json）
```

两条轨迹必须位于同一个采集时间目录。两段都成功后才从隐藏的 `.staging` 目录发布，避免出现只包含半条采集的数据目录。

## 5. 采集会话行为

启动命令：

```bash
UV_CACHE_DIR=/tmp/uv-cache uv run piper-x-collect teleop-session \
  --config configs/tasks/grab_rotating_red_square_into_blue_plate.yaml \
  --teleop-config configs/teleop/pika_sense_piper_x.example.yaml \
  --reverse-recording
```

关键行为：

- 两台相机在预热阶段并行启动，预热帧不保存。
- 第一段按空格停止后，调整场景，再按空格开始第二段。
- 两段都完成后统一执行保留/删除选择；删除会删除当前 collection 的两条轨迹及相机参数。
- 按空格开始同一 tag 下的下一次采集，按 `q` 结束当前会话；下一次采集仍复用相机和遥操进程。
- `--on-complete save` 或 `--on-complete delete` 可跳过人工保留/删除选择。

## 6. 相机参数

每次相机预热会读取实际运行参数；批次根目录的 `camera_parameters.json` 保存输入配置和摘要。RealSense 参数 JSON 只包含启用相机的静态采集配置；运行快照只记录本次启用的 RGB/深度流、设备名称/序列号/固件/产品线、配置中实际应用的 option 当前值，以及当前流内参、深度到彩色外参和深度比例。未启用深度时不保存深度流和深度比例。不会枚举或保存 SDK 全部支持的选项、流 profile 或 Advanced Mode JSON。

需要单独读取当前相机参数时，使用 `tool/realsense_camera/snapshot.py`；需要观察画面并自动曝光/白平衡时，使用 `tool/realsense_camera/preview.py`。两者都要求传入采集 YAML，并通过 `--name` 和 `--purpose` 指定参数文件名及用途；输出目录统一为 `configs/camera/`。

输入参数文件中的 `cameras[].options` 会在 RealSense 启动后调用 `sensor.set_option` 应用；设置失败会拒绝本次采集。实机运行快照同步到 `configs/camera/*.json` 的 `devices` 字段和 batch 参数文件；参数摘要忽略 `devices`，只锁定静态相机配置。

如果新增相机适配器，应实现 `CameraDevice.parameters()`，至少返回可序列化字典；不支持参数读取时返回空字典并在文档中说明。

## 7. 轨迹查看器

`trajectory-viewer` 支持以下文件名：

- 旧格式：`trajectory.hdf5`；
- 双向格式：`normal_trajectory.hdf5`、`reverse_trajectory.hdf5`。

查看器列表会显示 collection 编号和“正向/逆向”方向，并根据轨迹文件名前缀读取对应质量文件。修改输出文件命名时，必须同步修改 `trajectory_viewer.py` 的扫描、质量文件映射和页面显示。

## 8. 验证命令

优先使用仓库内 Python 3.10 环境：

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 UV_CACHE_DIR=/tmp/uv-cache uv run pytest -q
UV_CACHE_DIR=/tmp/uv-cache uv run python -m py_compile src/taiyi_piper_x_collect/*.py src/taiyi_piper_x_collect/devices/*.py
git diff --check
```

真实硬件采集前，先执行 `preflight`，确认相机、Piper-X 和夹爪反馈均通过，再运行遥操会话。不要在没有现场安全确认的情况下启用 `robot.initial_pose.enabled` 或启动真实遥操。

## 9. 维护注意事项

- 不要把 SSH 私钥、真实标定秘密或现场身份信息提交到仓库。
- 修改 `SessionConfig` 后，要同步更新示例配置、任务配置、测试和本文。
- 修改 HDF5 文件名或目录结构后，要同步更新查看器、校验命令和采集文档。
- 修改删除逻辑时，必须验证删除范围仍然位于 `session.output_root` 内，不能允许删除输出根目录本身。
- Piper-X 起始位姿超时会触发 pyAgxArm 电子急停；采集流程不会自动调用 `reset()`。手动恢复工具的按钮会在二次确认后调用它，但悬空或带负载时禁止操作。
- 现场恢复工具位于 `tool/piper_x_control/`，仅调用仓库内 pyAgxArm，不修改 `/home/cv/pika_ros`；“停止保持”使用阻尼电子急停，“恢复使能”在二次确认后调用 `reset()` 清除急停，再调用 `enable()`。
- 完整 pytest 依赖环境可能加载系统 ROS 插件；遇到 `launch_testing` 或 `lark` 冲突时使用 `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`。
