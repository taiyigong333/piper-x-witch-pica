# 实际采集逐指令操作说明

本文用于任务 `pick up the corn and put it on the plate`。实际采集配置是 `configs/pick_up_the_corn_and_put_it_on_the_plate.yaml`，输出写入 `/home/cv/gcj/data_collect/data/corn_in_plate`。本项目不修改 `/home/cv/pika_ros`。

## 0. 现场检查

确认急停可用、工作区无人、Piper-X、原装夹爪、D435、D405 和 Pika Sense 均已接通。确认 `can0` 已由现场人员按设备要求启动，且没有其他控制器占用 CAN 或 Pika Sense USB。以下命令只查看本项目可识别的残留遥操进程：

```bash
cd /home/cv/gcj/data_collect/piper_x_with_pica/code
UV_CACHE_DIR=/tmp/uv-cache uv run piper-x-collect teleop-status
```

只有确认列出的进程都属于上一轮遗留遥操时，才可关闭它们：

```bash
UV_CACHE_DIR=/tmp/uv-cache uv run piper-x-collect teleop-stop --terminate
```

## 1. 准备采集环境

在采集终端执行。该终端只使用项目的 uv Python 3.10 环境，不能在这里执行 ROS launch：

```bash
cd /home/cv/gcj/data_collect/piper_x_with_pica/code
git submodule update --init --recursive
UV_CACHE_DIR=/tmp/uv-cache uv sync --extra dev --extra realsense
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 UV_CACHE_DIR=/tmp/uv-cache uv run pytest tests/test_config.py
```

最后一条只检查 YAML 配置和 Python 配置约束，不访问 CAN 或相机。通过后，检查任务配置的关键值：

```bash
sed -n '1,180p' configs/pick_up_the_corn_and_put_it_on_the_plate.yaml
```

确认两台相机序列号、`robot.firmware_version`、工具偏移和 `initial_pose` 与现场一致。`initial_pose.enabled: true` 会在遥操会话开始前使机械臂低速回到文件中的关节姿态；当前位置不安全或不应自动移动时，先将其改成 `false`。

## 2. 校准 Pika 基站

首次使用本机、基站位置改变、频道改变或定位不稳定时，执行强制校准。此命令会调用现有 Pika 工具，可能要求现场人员操作：

```bash
cd /home/cv/gcj/data_collect/piper_x_with_pica/code
UV_CACHE_DIR=/tmp/uv-cache uv run piper-x-collect calibrate-base \
  --teleop-config configs/pika_sense_piper_x.example.yaml \
  --mode force
```

已完成强制校准、只需查看定位状态时，使用：

```bash
UV_CACHE_DIR=/tmp/uv-cache uv run piper-x-collect calibrate-base \
  --teleop-config configs/pika_sense_piper_x.example.yaml \
  --mode diagnose
```

## 3. 真实设备预检和当前位置记录

机械臂保持静止时执行预检。它只读取两台 RealSense、Piper-X 与原装夹爪反馈，不移动机械臂：

```bash
cd /home/cv/gcj/data_collect/piper_x_with_pica/code
UV_CACHE_DIR=/tmp/uv-cache uv run piper-x-collect preflight \
  --config configs/pick_up_the_corn_and_put_it_on_the_plate.yaml
```

只有输出的 `result` 为 `pass` 才继续。预检成功后，读取并记录当前关节和 TCP；此命令同样不发送控制帧：

```bash
UV_CACHE_DIR=/tmp/uv-cache uv run piper-x-collect read-piper-x-state \
  --config configs/pick_up_the_corn_and_put_it_on_the_plate.yaml \
  --wait-s 1.0
```

若要把这次输出作为下一次起始位姿，将 `joint_positions_rad` 的六个值替换进任务配置，再重新运行配置测试：

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 UV_CACHE_DIR=/tmp/uv-cache uv run pytest tests/test_config.py
```

## 4. 正式遥操采集

正式流程只运行下面的 `teleop-session` 命令。它会依次预检、移动到起始位姿、启动 Pika Sense、在 `pika` Conda 环境启动 `teleop_single_piper_x.launch.py`、采集数据并关闭它们。不要在此流程运行期间手工启动下一节的两个 ROS 命令。

```bash
cd /home/cv/gcj/data_collect/piper_x_with_pica/code
UV_CACHE_DIR=/tmp/uv-cache uv run piper-x-collect teleop-session \
  --config configs/pick_up_the_corn_and_put_it_on_the_plate.yaml \
  --teleop-config configs/pika_sense_piper_x.example.yaml
```

终端交互顺序如下：

1. 看到“已按现场情况完成基站校准”后，按一次空格。
2. 预检通过且确认工作区安全后，按一次空格。此后程序会移动 Piper-X 到 `initial_pose`。
3. Pika 进程就绪后，快速开合 Sense 夹爪两次以开启遥操，确认 Piper-X 实际跟随，再按一次空格开始写入轨迹。
4. 动作完成后，保持 Sense 遥操仍在运行，按一次空格停止采集并等待 HDF5、`quality.json`、`manifest.json` 和校验和写完。
5. 看到写盘完成提示后，快速开合 Sense 夹爪两次以停止实体遥操，再按一次空格，让程序关闭 ROS 进程。
6. 最后按空格保留数据，按 `d` 删除本条数据，按 `q` 保留数据。

要连续采集多条轨迹，改用：

```bash
UV_CACHE_DIR=/tmp/uv-cache uv run piper-x-collect teleop-session \
  --config configs/pick_up_the_corn_and_put_it_on_the_plate.yaml \
  --teleop-config configs/pika_sense_piper_x.example.yaml \
  --repeat
```

## 5. 校验和查看

`teleop-session` 输出的 `trajectory_path` 是本条数据目录。将其代入下列命令，先进行只读结构校验：

```bash
cd /home/cv/gcj/data_collect/piper_x_with_pica/code
UV_CACHE_DIR=/tmp/uv-cache uv run piper-x-collect validate \
  <trajectory_path>/trajectory.hdf5 \
  --config configs/pick_up_the_corn_and_put_it_on_the_plate.yaml
```

再启动只读查看器：

```bash
UV_CACHE_DIR=/tmp/uv-cache uv run piper-x-collect trajectory-viewer \
  --root /home/cv/gcj/data_collect/data/corn_in_plate
```

浏览器打开 `http://127.0.0.1:8765`。逐帧检查两路 RGB、关节、TCP、原装夹爪宽度和质量报告；确认无误后在终端按 `Ctrl-C` 关闭查看器。

## 6. 手工启动 Pika 的诊断方式

只在排查 Pika/ROS 问题时使用本节。它与第 4 节的 `teleop-session` 互斥，不能同时运行。终端 1：

```bash
source ~/pika_ros/install/setup.bash
cd ~/pika_ros/scripts
bash start_single_sensor_whit_teleop.bash
```

终端 2：

```bash
source ~/pika_ros/install/setup.bash
source ~/miniconda3/etc/profile.d/conda.sh
conda activate pika
export PYTHONPATH=$CONDA_PREFIX/lib/python3.10/site-packages:$PYTHONPATH
ros2 launch pika_remote_agx_arm teleop_single_piper_x.launch.py
```

诊断结束后在两个终端分别按 `Ctrl-C`，再执行第 0 节的 `teleop-status` 确认没有残留进程。手工启动遥操时若只需按固定时长采集，可在第三个终端执行；该命令不移动机械臂：

```bash
cd /home/cv/gcj/data_collect/piper_x_with_pica/code
UV_CACHE_DIR=/tmp/uv-cache uv run piper-x-collect collect \
  --config configs/pick_up_the_corn_and_put_it_on_the_plate.yaml \
  --duration 60
```
