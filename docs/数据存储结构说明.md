# 数据存储结构说明

本文说明 Piper-X 数据采集结果在磁盘和 HDF5 文件中的实际组织方式。采集配置中的 `session.output_root` 是数据根目录。

## 1. 磁盘目录

```text
<output_root>/
└── batch_<batch_tag>/                         # 批次目录
    ├── camera_parameters.json                 # 批次锁定的相机配置和运行快照
    └── <collection_time>/                     # 一次完整采集，时间精确到微秒
        ├── forward/                            # 正向轨迹
        │   ├── normal_trajectory.hdf5
        │   ├── normal_trajectory_quality.json
        │   ├── normal_trajectory_manifest.json
        │   └── normal_trajectory_checksums.sha256
        └── reverse/                            # 逆向轨迹
            ├── reverse_trajectory.hdf5
            ├── reverse_trajectory_quality.json
            ├── reverse_trajectory_manifest.json
            └── reverse_trajectory_checksums.sha256
```

旧版本可能使用 `trajectory.hdf5`，查看器仍兼容该名称。双向采集时正向和逆向轨迹位于同一个 `<collection_time>` 目录。采集过程中先写入隐藏的 `.staging/forward` 和 `.staging/reverse`，两段都成功后才发布到正式目录，避免留下半条采集。

同一个 `batch_<batch_tag>` 下可以连续采集多个 collection。批次首次采集会写入 `camera_parameters.json`；后续采集的相机参数摘要必须一致，否则采集会被拒绝。

## 2. HDF5 顶层结构

每条 `*_trajectory.hdf5` 是一个独立轨迹文件。数据集长度以 `/metadata/trajectory_length` 为准，相机时间轴和所有 `*_align` 时序数据应与它一致。

```text
/
├── metadata/
├── robot_model/
├── base_to_robot_transformation/              # 配置了 base_to_robot 时存在
├── camera_model/
├── camera_color_resolution/
├── camera_color_channel/
├── camera_depth_resolution/                    # 启用深度时存在
├── camera_intrinsics/
├── camera_extrinsics/                          # 配置了相机外参时存在
├── acquisition_config/
├── end_effector_model/                         # 夹爪配置启用时存在
├── camera_observations/
└── puppet/
```

## 3. 元数据和静态配置

`/metadata` 包含 `language_instruction`、`data_type`、`data_format_version`、`collection_time`、`collector`、`pose_representation`、`batch_tag` 和 `trajectory_length`；仿真数据还可能包含 `sim_assets`。

其他静态字段包括：

- `/robot_model/robot_single`：机器人名称；
- `/camera_model/<camera_name>`：相机型号；
- `/camera_color_resolution/<camera_name>`：`[width, height]`；
- `/camera_color_channel/<camera_name>`：颜色通道顺序；
- `/camera_depth_resolution/<camera_name>`：启用深度时的 `[width, height]`；
- `/camera_intrinsics/<camera_name>/matrix` 和 `dist_coeffs`：运行时彩色内参；
- `/camera_extrinsics/<camera_name>`：配置的 base 到相机外参；
- `/acquisition_config/`：输入配置名、启用模态、对齐策略、机器人频率、相机频率、最大对齐年龄和 HDF5 批量大小。

## 4. 相机观测数据

```text
/camera_observations/
├── timestamp             # shape=(N,), float64，秒
├── is_intervene          # shape=(N,), bool
├── color_images/         # 启用 RGB 时存在
│   ├── camera_front      # N 个 JPEG 编码 uint8 可变长数组
│   └── camera_wrist_right
└── depth_images/         # 启用 depth 时存在
    ├── camera_front      # N 个深度图编码 uint8 可变长数组
    └── camera_wrist_right
```

每个相机数据集的第 `i` 项对应 `timestamp[i]`。图像保存为 HDF5 可变长 `uint8` 字节，读取后需要使用 JPEG/深度图解码器恢复像素矩阵。

## 5. 机器人与夹爪时序

`/puppet` 中每个时序组都包含 `timestamp`、`is_intervene`、`data`。`data` 第一维是样本数，第二维由模态决定：

```text
/puppet/
├── arm_single_position_raw/       # shape=(M, joint_count)
├── arm_single_position_align/     # 与相机时间轴对齐，shape=(N, joint_count)
├── end_effector_single_pose_raw/  # shape=(M, 6 或 7)
├── end_effector_single_pose_align/# shape=(N, 6 或 7)
├── end_effector_single_position_raw/   # 夹爪位置，shape=(M, 1)
└── end_effector_single_position_align/ # shape=(N, 1)
```

只有配置启用的模态会创建对应组。`raw` 是设备实际反馈时间轴；`align` 是与相机帧一一对应的最新机器人状态。夹爪位置以米写入。

## 6. 质量、清单和校验文件

每条轨迹关闭 HDF5 后会生成同前缀文件：

- `*_quality.json`：结构校验、帧数、时间戳、图像可解码性、重复帧比例和人工复核状态；
- `*_manifest.json`：轨迹路径、采集标识和文件清单；
- `*_checksums.sha256`：相关文件 SHA-256 校验值。

推荐先执行结构校验：

```bash
UV_CACHE_DIR=/tmp/uv-cache uv run piper-x-collect validate \
  <output_root>/batch_1/<collection_time>/forward/normal_trajectory.hdf5 \
  --config configs/tasks/grab_rotating_red_square_into_blue_plate.yaml
```

## 7. 读取建议

先用 `/metadata/trajectory_length` 和 `/camera_observations/timestamp` 确定有效长度，再按同一索引读取各相机图像和 `puppet/*_align` 数据。不要把 `raw` 数据直接与相机帧按数组下标配对，应使用时间戳或已经对齐的 `align` 数据。批次级 `camera_parameters.json` 用于确认相机配置和运行参数，不替代 HDF5 中的内参、外参和轨迹数据。
