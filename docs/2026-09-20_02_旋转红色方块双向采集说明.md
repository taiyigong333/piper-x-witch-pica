# 旋转红色方块双向采集说明

本文用于任务“夹取旋转平台上旋转的红色方块，并将其放入蓝色盘子”的双向数据采集。采集配置为 `configs/tasks/grab_rotating_red_square_into_blue_plate.yaml`，任务描述固定为：

配置中的 `session.batch_tag` 是批次编号，填写正整数（例如 `1`、`2`、`3`）。每次开始新批次前手动修改该字段；不同批次会写入不同的 `batch_<编号>` 文件夹。同一个 tag 可以连续采集多次，每次完整采集进入独立的精确到微秒的采集时间目录。

目录结构如下：

```text
batch_1/
├── camera_parameters.json
└── <采集时间>/
    ├── forward/
    │   ├── normal_trajectory.hdf5
    │   ├── normal_trajectory_quality.json
    │   ├── normal_trajectory_manifest.json
    │   └── normal_trajectory_checksums.sha256
    └── reverse/
        ├── reverse_trajectory.hdf5
        ├── reverse_trajectory_quality.json
        ├── reverse_trajectory_manifest.json
        └── reverse_trajectory_checksums.sha256
```

```text
grab the rotating red square and put it into the blue plate
```

## 1. 采集目标

需要连续采集两条独立轨迹：

1. 正向轨迹：从旋转平台夹取红色方块，放入蓝色盘子。
2. 反向轨迹：从蓝色盘子取出红色方块，放回旋转平台。

第二条轨迹在采集时保持正常时间顺序。采集完成后，再将第二条轨迹离线倒放，并保存到新的目录，用作第一条任务的反向数据。采集过程中禁止实时倒放或修改帧顺序。正向和反向轨迹完成后才进行批次确认和最终落盘处理。

## 2. 启动命令

在项目根目录执行：

```bash
UV_CACHE_DIR=/tmp/uv-cache uv run piper-x-collect teleop-session \
  --config configs/tasks/grab_rotating_red_square_into_blue_plate.yaml \
  --teleop-config configs/teleop/pika_sense_piper_x.example.yaml \
  --reverse-recording
```

如需自动保留两条轨迹，可增加 `--on-complete save`；如需自动删除两条轨迹，可增加 `--on-complete delete`。不指定时，程序会在每条轨迹写盘后提示按键选择。

## 3. 现场操作顺序

1. 确认急停、工作区、Piper-X、夹爪、D435、D405 和 Pika Sense 状态正常。
2. 按提示确认安全，程序并行启动两台相机并开始预热，同时移动机械臂到配置的初始位姿。
3. 等待遥操节点就绪，快速开合 Sense 夹爪两次启用遥操，确认机械臂跟随后按空格开始第一段录制。
4. 完成“夹取旋转红色方块并放入蓝色盘子”，保持遥操运行，按空格停止第一段录制。
5. 等待第一段轨迹完成写盘。相机和遥操不会关闭；按提示调整物体到蓝色盘子中，并按空格开始第二段录制。
6. 完成“从蓝色盘子取出红色方块并放回旋转平台”，按空格停止第二段录制。
7. 第二段结束后等待程序完成两条轨迹的统一写盘和相机参数保存，不在第一段结束时删除。
8. 两条轨迹都完成后，程序统一生成批次文件和 RealSense 参数文件；双击 Sense 夹爪停止实体遥操，按空格结束会话。
9. 在本次采集确认提示中选择保留或删除。删除会同时删除当前采集时间目录中的正向和逆向轨迹，不影响同一 tag 下的其他采集。
10. 按空格直接开始同一 tag 下的下一次采集；按 `q` 结束。同一会话中相机和遥操保持运行。

## 4. 帧保存规则

- 相机在遥操准备前启动，并持续读取预热帧。
- 预热阶段只用于稳定设备和曝光，不创建 HDF5，也不保存预热帧。
- 只有按空格开始某一段录制后读取的有效对齐帧才会进入该段 HDF5。
- 按空格停止录制后，正在读取、编码或等待入队的帧会被丢弃，不作为尾帧写入。
- 两台相机的启动调用并行执行；每次组帧时仍会同时读取两路相机后再写入对齐数据。
- 每次采集的两段轨迹位于同一个采集时间目录的 `forward/` 和 `reverse/` 子目录，名称分别为 `normal_trajectory.hdf5` 和 `reverse_trajectory.hdf5`，对应的质量、manifest 和校验文件也带有相同前缀。
- 批次 `camera_parameters.json` 只记录实际启用的相机流、设备标识、配置中应用的 option 当前值和对应标定；本任务未启用深度，不保存深度流参数、完整 SDK option 目录或未使用的 profile。

## 5. 采集后检查

记录程序输出的两条 `trajectory_path`。分别执行结构校验：

```bash
UV_CACHE_DIR=/tmp/uv-cache uv run piper-x-collect validate \
  <trajectory_path>/trajectory.hdf5 \
  --config configs/tasks/grab_rotating_red_square_into_blue_plate.yaml
```

确认两条轨迹均通过校验后，再对第二条轨迹执行离线倒放，并将结果写入新的输出目录。原始第二条轨迹必须保留，不能被倒放结果覆盖。
